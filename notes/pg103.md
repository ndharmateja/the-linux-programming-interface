Let's clear the fog completely.

The book is confusing because it lumps a **theoretical Unix standard rule** together with **practical Linux rules**.

Here is the entire concept, stripped down into byte-sized truths.

---

## 1. The "Standard Loophole" Error (Never happens on Linux)

When the book says *"the system call returns an error if length exceeds current size,"* it is talking about **ancient, non-Linux Unix operating systems**.

* **On Linux:** If you make a file bigger using `truncate()` or `ftruncate()`, it **never** throws an error for that reason. It just safely expands the file with zeros.

---

## 2. The Real Linux Errors (When your code will actually fail)

If you are running your program on Linux today, `truncate()` or `ftruncate()` will only return `-1` (fail) for these specific, logical reasons:

### Reason A: You opened the file wrong (`EBADF`)

* **The Culprit:** You used `ftruncate(fd, length)`, but you opened that file descriptor as read-only.
* **The Rule:** You cannot truncate a file you don't have write permissions for.
* **Fix:** Ensure you used `O_WRONLY` or `O_RDWR` in your `open()` call.

### Reason B: You targeted the wrong type of file (`EINVAL`)

* **The Culprit:** You tried to run `ftruncate()` on something that isn't a normal file on your hard drive.
* **The Rule:** You cannot truncate a **Pipe**, a **Socket**, or a **Directory**. They don't have a file length cursor that can be chopped or extended.

### Reason C: OS or Disk Limits (`EFBIG` / `ENOSPC`)

* **The Culprit:** You asked to extend the file to a size that is physically impossible.
* **The Rule:** The call fails if the length parameter is a negative number, if it exceeds your system's maximum file size limit, or if the drive is 100% full.

### Reason D: File System Permissions (`EACCES` / `EROFS`)

* **The Culprit:** You used the pathname version `truncate("/path/to/file", length)`, but your user account doesn't have permission to write to that directory, or the entire hard drive is mounted as "Read-Only".

## Summary Checklist

| If you try to... | On Linux, does it error? | Why? |
| --- | --- | --- |
| Make a file **smaller** | **No error** | It cleanly chops off the extra bytes. |
| Make a file **bigger** | **No error** | It expands it with space-saving holes/null bytes. |
| Truncate an **`O_RDONLY` file descriptor** | **ERROR (`EBADF`)** | You didn't ask for write permissions. |
| Truncate a **Pipe or Socket** | **ERROR (`EINVAL`)** | Sockets and pipes cannot have a fixed length. |
