This confusion is very common because the shell is doing a lot of "magic" in the background. To understand this, you have to look at how programs expect to get their data.

Most command-line tools (like `diff`) were written to open a **file path** (e.g., `/home/user/notes.txt`). They weren't originally designed to look at a **pipe** or **standard input**.

---

### 1. The "Hyphen Hack" (`-`)

Because programmers wanted to use these tools in pipelines, they invented a "hack": if you pass a single hyphen `-` as a filename, the program is hard-coded to say, *"Oh, the user doesn't want a file on disk; I should just read from standard input instead"*.

**The Problem:**

* **Inconsistency:** Not every programmer added this "hyphen check" to their code. If a program doesn't support it, it will literally look for a file named `-` on your hard drive, fail to find it, and crash.
* **Ambiguity:** Many tools use `-` to mean "stop looking for flags" (like `-l` or `-v`), which creates a mess if you actually want to use it as a filename.

---

### 2. The Clean Solution: `/dev/fd/n`

Instead of relying on every programmer to support the hyphen hack, Linux provides a **universal path** that points to your process's open files.

Remember that every process starts with three open file descriptors:

* **0**: Standard Input (`stdin`)
* **1**: Standard Output (`stdout`)
* **2**: Standard Error (`stderr`)

The `/dev/fd/` directory makes these descriptors look like **actual files on disk**.

#### The Comparison

| Method | Command | How the Program Sees It |
| --- | --- | --- |
| **The Hack** | `ls | diff - oldfile` | `diff` has to manually check: "Is the filename a dash? If yes, use `stdin`." |
| **The Clean Way** | `ls | diff /dev/fd/0 oldfile` | `diff` just thinks: "I'm opening a file at this path." It doesn't need to know it's actually a pipe. |

---

### 3. Why this matters for you

By using `/dev/fd/0`, you can force **any** program that expects a filename to work with a pipe, even if the person who wrote the program never heard of the "hyphen hack".

You are effectively "tricking" the program. It asks the kernel to open a file path, and the kernel secretly hands it a pipe instead.

---

> **Key Takeaway:** `/dev/fd` is a bridge. It allows **Path-based programs** to talk to **Descriptor-based streams** (like pipes) without needing any special code changes.
